## Decisions for you to confirm

| # | Decision | Recommendation and reason |
|---|---|---|
| 1 | **What the state file holds:** `ServiceId`, `Mode` (default Rehearse), `Dismissals` (a list of rule name plus an optional target, both text), `LogPromptDeclined` (true once the user answers No to "Log this as a live service?"). | Exactly what LIB-013 lists. Dismissals are plain text keys because the check rules don't exist until C6.2. Defining the field now avoids changing the file shape later. |
| 2 | **Saving the state file: the last write wins, with the other safety rules kept.** The save is still atomic, still writes nothing if the content is unchanged, and still never overwrites a file from a newer app version. A damaged state file loads as the defaults and is repaired by the next save. | LIB-013. If both machines change the Mode, the latest choice is the right one. No Reload / Save as copy prompt for a mode switch. |
| 3 | **Deleting a Service doesn't delete its state file here.** The Service editor (C2.5) deletes both. A state file with no Service is harmless and ignored. | Keeps the repository simple. Nothing reads a state file without its Service. |
| 4 | **The Scripture Category's ID is `793b069a-9c4a-482c-9b09-f94a9b196401`**, named "Scripture" by default. It is added in memory whenever `categories.json` is loaded without it, and written only when categories are next saved. A category list without it can't be saved. | CAT-010. Loading never writes files (as in C1.3 decision 7), and both machines add the same ID, so Drive never sees two. Refusing the save is how "can't be deleted" is enforced in storage. Renaming is allowed. |
| 5 | **One "skip list in force" function, and `SlidePosition` takes the Service Item instead of a skip list.** `SkipRules.InForce(item, show)` returns the item's skips, or none for a Show with audio Cues (SVC-025). `SlidePosition.For(show, slide, item)` calls it, with `item` null for a Show viewed outside a Service. | Changing the signature makes the mistake impossible: no caller can hand over a raw skip list. C1.5 navigation uses the same function. |
| 6 | **"Stands alone" (TMR-009) means:** ignoring whitespace and empty paragraphs, the Text Box contains exactly one Timer token and nothing else. Otherwise resolution reports `TimerTokenNotAlone(timer name, text box)`. The slide still renders as it does today. | A plain, testable rule. The problem goes to the pre-service check. How such a box renders live is C5.1's concern. |
| 7 | **Where each trigger is allowed (ACT-010..016):** | `ServiceStarted`: Service (and Service Template). `ShowStarted`, `ShowEnded`: Show, Service Item. `SlideDisplayed`, `SlideEnded`: Slide, Service Item. `TimerExpired`: Slide, Service (and Service Template). `AudioEnded`: Show. One domain function answers "is this trigger allowed at this level". **Saving refuses an Action whose trigger isn't allowed where it is**, like other invalid objects (C1.3 decision 6). The Action editor (C5.2) will only offer allowed triggers. |
| 8 | **Variable and Timer names are checked when saving:** valid characters (VAR-001, TMR-001) and unique within the Service or Service Template, ignoring case. | Timers follow the Variable rules now. Uniqueness for Variables was planned for C3.2. Doing both here is the same few lines, and C3.2 only adds the UI. |
| 9 | **A missing warning color means no color change** (TMR-006). Documented on `CountdownTimer.WarningColorHex`. No code change: resolution already passes it through as optional. | Owner decision 2026-11-23. Red as the default for new Timers is the Timer editor's job (C5.1). |
| 10 | **Schema version 1 is amended, not bumped.** Golden files are regenerated and reviewed. `ServiceState` starts at version 1. | Owner decision 2026-11-23. No real Library exists yet. |

## C1.3c-1: Domain

**Model changes**
- `Service`: remove `Mode`. `ServiceMode` stays (used by `ServiceState`).
- New `ServiceState` record (decision 1) and `CheckDismissal(Rule, Target?)`. Added to the JSON context and `SchemaVersions` (version 1).
- `LibrarySettings`: remove `DefaultScriptureTemplateId`.
- `Command`: add `Normal` (`"normal"`, ACT-033). Doc comments on `Clear`, `Black`, `Logo`: set, not toggle.
- `CountdownTimer.WarningColorHex`: doc comment (decision 9).
- New `BuiltInCategories`: `ScriptureId`, `Scripture` (the default Category), `EnsureIn(CategoryList)` (adds it if missing, otherwise returns the list unchanged).

**Logic**
- `SkipRules.InForce(ShowItem, Show)`; `SlidePosition.For(Show, Slide, ServiceItem?)` (decision 5).
- `ServiceCopying.FromTemplate` and `Duplicate`: stop setting `Mode`. A new Service has no state file, which means Rehearse.
- `SlideResolver`: report `TimerTokenNotAlone` (decision 6). New `RenderProblem` subtype.
- New `ActionLevel` enum (`Slide`, `Show`, `ServiceItem`, `Service`, `ServiceTemplate`) and `ActionRules.IsAllowed(ActionTrigger, ActionLevel)` (decision 7).
- `VariableNames.IsValid` is reused for Timer names (no new rule).

**Tests (domain)**
1. **LIB-013, MODE-001:** a `Service` serializes with no `mode` field. `ServiceState` round trips. Golden service file has no mode.
2. **ACT-033:** `Normal` survives a round trip with its type (golden service file gains one).
3. **CAT-010:** `EnsureIn` adds Scripture to an empty list, leaves a list that has it (even renamed) unchanged, and the ID matches the constant.
4. **SVC-025 / CCLI-004:** a cued Show with a stale skip list: `InForce` is empty, and the copyright notice lands on the Show's real first slide. An uncued Show still honors skips. Outside a Service (item null), nothing is skipped. Existing copyright tests move to the new signature.
5. **TMR-009:** a box with only `{{timer:X}}` (plus whitespace or empty paragraphs) reports nothing. Timer token plus text, two Timer tokens, or a Timer token plus a Variable token reports `TimerTokenNotAlone`.
6. **ACT-010..016:** the full trigger × level table.
7. **Service copying:** existing tests no longer assert `Mode`. Instead, a new Service and a duplicate have no mode at all (Rehearse comes from the absent state file, tested in storage).

## C1.3c-2: Storage

- `LibraryLayout.ServiceStateFolder` (`service-state/`).
- `IServiceStateRepository` on `ILibrary.ServiceStates`: `Load(Id<Service>)` (missing or damaged gives the defaults, with the status reported), `Save(ServiceState)` (decision 2), `Delete(Id<Service>)`. Implemented over `LibraryFileStore` with a new "overwrite" save path that keeps the atomic, unchanged and newer-version rules but skips the conflict check.
- `FolderLibrary.Categories`: `Load` passes the list through `BuiltInCategories.EnsureIn` (decision 4).
- `SaveValidation`:
  - category list without the Scripture Category (decision 4)
  - triggers not allowed at their level, for Shows (and their Slides), Services (and their items and local Shows), Service Templates (decision 7)
  - Variable and Timer names: valid and unique (decision 8)
  - `ServiceState` with an empty `ServiceId`

**Tests (storage)**
1. **LIB-013:** state round trip in `service-state/{id}.json`. Missing file gives Rehearse, no dismissals and not declined. Damaged file gives the defaults and the next save repairs it. Save over a file changed elsewhere succeeds (last write wins). Unchanged content writes nothing. A newer-version state file is not overwritten. **State files never appear in `Services.LoadAll`.**
2. **LIB-008:** the "only Library files land in the Library" test gains a state save and expects `service-state/`.
3. **CAT-010:** loading a missing or old `categories.json` returns Scripture without writing any file. Saving a list without it is `Invalid`. Saving a renamed one works.
4. **Validation:** Actions with disallowed triggers at each level are `Invalid`, with the place named. Duplicate Variable names (`Preacher` and `preacher`), duplicate Timer names, and invalid characters are `Invalid`.
5. Existing storage tests whose sample data now breaks a rule are corrected (for example a sample Action with a trigger at the wrong level).
