Size M, throwaway. Adds a **Rich text** tab to `spike/ChurchSlides.Spike` (from C0.2). No changes to `src/` or `tests/`.
FRD: PLT-008 (c), SLD-005, SLD-021, SLD-022, SLD-023, SLD-025 (cost only), SLD-026, SLD-027, SLD-028, TPL-024, TPL-025, VAR-006, TMR-009, SAFE-003 (D-2 only).

**Status: agreed by the owner 2026-11-23 (all five decisions). Ready to execute.**

## Goal

Answer before C2.1 and C2.3 are planned: can a WPF `RichTextBox` edit our own `RichText` model (D-3) without losing or inventing formatting, and does a `FormattedText` renderer (D-4) draw the same text with the same line breaks? Find the control's quirks (paste, tokens, undo, caret, fonts) while they are cheap to design around. Outcome: a verdict on D-3/D-4 and a quirk list, written into `docs/SPIKE-RESULTS.md` at G0.

## C0.3a: Converter and renderer (first commit)

- `ChurchSlides.Spike.csproj`: `ProjectReference` to `src/ChurchSlides.Domain` (decision 1).
- `FlowConverter.cs`: `RichText` → `FlowDocument` and back. Paragraph ↔ `Paragraph` (margin 0); `TextRun` ↔ `Run`. Only **local** values are read back (`ReadLocalValue`), so a property the user never set stays null (TPL-024). Font size: relative to canvas height (SLD-005) ↔ device-independent pixels at the editor's scale. Adjacent runs with equal format are merged, since the control splits runs freely. Box-level alignment and line spacing (SLD-023) go on the document, not per paragraph.
- `RichTextRenderer.cs`: draws a Text Box's `RichText` with `FormattedText` (range setters per run) into a `DrawingVisual`, with Template-style defaults for unset properties, horizontal and vertical alignment, line spacing, and an overflow flag from measured height (SLD-028). Optional geometry outline (decision 5).
- `RichTextSamples.cs`: about eight fixed samples: hymn verse with one bold word; mixed fonts and sizes in a line; colored range across a line break; italic chorus with explicit and default runs side by side; long text that overflows; each token kind with formatting on it (VAR-006); a lone Timer token, and one next to text (TMR-009); a font that isn't installed (fallback must match).
- **Rich text tab:** sample picker; the `RichTextBox` and the renderer's bitmap side by side at the same size, over a church background; overlay toggle; a live view of the current model as JSON; Clear formatting button (TPL-025).
- **Automatic run (S3):** every sample: model → document → model equal; render compare figures (decision 4). Seeded random documents (500) round-trip. Scripted edits through the control's API (bold a range across runs, recolor part of a token, type inside a bold run, delete across paragraphs) produce the model expected. Timings: model → document, document load, renderer per slide, with and without outline, keystroke to next frame on a 200-word box.

## C0.3b: Tokens, paste and undo (second commit)

- `TokenChips.cs`: both designs (decision 2), insert menu for each token kind. A Timer token is only inserted into an empty box (TMR-009).
- `PasteFilter.cs`: `DataObject.Pasting` handler with the three modes (decision 3) and a "what was dropped" note.
- **Undo (D-2):** `IsUndoEnabled = false`; Ctrl+Z / Ctrl+Y bound to a small snapshot stack of `RichText` taken on typing pauses. Records whether the caret and selection can be restored after a snapshot is reloaded.
- **Checklist (eyes):** Word paste in each mode; chip behaviour (caret, select, delete, bold, copy-paste within the box) for both designs; typing feel on the church PC; editor and renderer look the same at the projector; Ctrl+Z / Ctrl+Y.

## Pass criteria (proposed; final judgement at G0)

| # | Pass |
|---|---|
| S3-a | Every sample and all random documents round-trip with no change. Scripted edits give the expected model. |
| S3-b | Renderer and editor have the same line breaks on every sample (equal line counts, no visible difference in the overlay). Pixel difference recorded. |
| S3-c | At least one chip design survives formatting, copy, paste, deletion and undo without corrupting the model. |
| S3-d | Keystroke to next frame under 50 ms on the church PC. Renderer under about 30 ms per slide. |
| S3-e | Unset properties stay unset through editing (Template defaults still apply). |

If S3-b fails, D-4 is revisited (draw the editor's `FlowDocument` instead). If S3-a or S3-c fails, the quirk list says what C2.3 must work around.
