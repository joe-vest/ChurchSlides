## Goal

The app notices when the other machine (through Drive) changes, adds or deletes a Library file, reloads just that file, and ignores its own saves and Drive's noise. Files that look like sync-tool copies are listed as problems, never loaded as extra objects. A missing Library folder is reported, not thrown. Shows can be found by typing part of the title, the lyrics or the CCLI number, ignoring case and accents. All of it is tested headless with `dotnet test`.

## Decisions for you to confirm

| # | Decision | Recommendation and reason |
|---|---|---|
| 1 | **A Library object file is loaded only if its name is `{its own Id}.json`.** Any other `.json` file in an object folder (`shows/`, `services/`, `templates/`, `service-templates/`, `service-state/`) is a Library problem and is not loaded: "looks like a sync conflict copy" when the name contains `(n)` or `conflict`, "copied or renamed file" when the name is a GUID but the contents carry another Id, "unexpected file" otherwise. | One rule covers every sync tool's naming (Drive `x (1).json`, Dropbox `x (… conflicted copy …).json`, OneDrive `x-PCNAME.json`) without a pattern list. It also makes duplicate Ids within a folder impossible, so LIB-009 duplicate detection is the same check (ARCH 9.1: contents win, so a copied file reads as a duplicate). Only top-level files are checked: Show Copies and Scripture slides inside Services may share Ids (STATUS follow-up). |
| 2 | **Non-`.json` files and `.saving` files are ignored silently**, anywhere. So are `media/`, `bibles/`, `logs/` and unknown folders. | Drive and Office drop `.tmp`, `~$…`, `desktop.ini` and similar. They are noise, not problems. Media changes matter to the image cache (C2.1), not here. |
| 3 | **Debounce per file, 500 ms of quiet.** Every event for a path (created, changed, renamed, deleted) restarts that path's quiet period. When it ends, the monitor looks at the file as it is now, so event types don't matter. No maximum wait. | Drive writes in bursts and through temp files. Looking at the final state instead of replaying events is simpler and can't get the order wrong. One setting. |
| 4 | **The debouncer is a pure class driven by time values** (`Add(path, now)`, `TakeDue(now)`), so tests need no sleeps. The thin `FolderWatcher` adapter feeds it from `FileSystemWatcher` and calls it from a timer. | Deterministic tests. The adapter is the only code that needs real-folder tests (two, with generous timeouts). |
| 5 | **Add `IClock` to Domain now** (`DateTimeOffset Now`, plus `SystemClock`). The watcher uses it, and Engine (C1.5, C5.1) will too. | CLAUDE.md rule 10 names it and it doesn't exist yet. Domain is the only assembly both Storage and Engine can see. One property: local and UTC time both come from a `DateTimeOffset`. |
| 6 | **Self-write suppression by content hash.** The monitor remembers the hash of every file it has seen. `FolderLibrary` tells it about every successful save and delete (an internal hook in `LibraryFileStore`). After the quiet period, a file whose hash equals the remembered one produces no change. | ARCH 8.3 says "our own saves are ignored by hash". The same check also drops Drive re-stamping a file without changing it (as in C1.3 decision 3). |
| 7 | **The monitor reports changes. It doesn't decide about open editors.** A change is `(Kind, Id, Added/Changed/Removed, Path, Stamp)`. The search index always updates. An editor holding that object (C2.x) keeps its draft and will get the C1.3 `Conflict` on save, which leads to Reload / Save as copy (LIB-006). | LIB-007 "if it isn't being edited" is an editor rule. Storage can't know what is open, and the save-time check already protects the draft. |
| 8 | **Changes are processed on whichever thread calls the monitor** (the adapter's timer thread). The app posts the results to the UI thread. The API stays synchronous. | ARCH 4.1: file work in the background, results posted back. Same as C1.3 decision 2. |
| 9 | **Library unavailable.** At startup, `LibraryFolder.Check(path)` returns `Ok`, `NotSet`, `Missing` or `NotAFolder` (an empty folder is `Ok`: a new Library). While running, a watcher error or the root folder disappearing reports `Unavailable`. When the folder is back, a full rescan reports what changed. The prompt to choose another folder is UI (C2.6 / C9.1). | LIB-010 at the storage level. Saves already fail softly (`IoFailed`). |
| 10 | **No search snapshot file in this chunk.** At startup the index is built by loading every Show on a background thread. `cache\search.idx` (ARCH 9.2) is left for C9.2 if the church machine shows startup is slow. | 2,000 small JSON files load in well under a second on most machines. A snapshot adds an invalidation scheme and a file format. Measure first (rule 7). |
| 11 | **Search rules.** Text is lowercased and accent-stripped (`é`→`e`, `ñ`→`n`), punctuation becomes spaces. Every word of the query must appear (as the start of a word or inside one) in the same field. Ranking, best first: title starts with the query, title matches, CCLI number equals the query, slide text matches. Ties sort by title. An empty query returns every Show, sorted by title. Filters: Kind and Category, combined with the query. Slide text is the Text Boxes' text without tokens and without slide labels. | CAT-003/004 as written, with one rule for multiple words. Labels ("Verse 1") would match everything. Tokens (`{{preacher}}`) aren't lyrics. |
| 12 | **The index is an immutable snapshot swapped on each update.** Searches read the current snapshot without locks. A search is a linear scan (ARCH 9.2). | Updates happen on a background thread while the UI types. Swapping an immutable list is the simplest safe way. |

## C1.4a: Watching

**Domain**
- `Time/IClock.cs`: `IClock { DateTimeOffset Now { get; } }`, `SystemClock`.

**Storage (new files)**
- `Watching/LibraryFileNames.cs`: `Classify(LibraryLayout, string fullPath)` returns `Ignored`, an object file `(LibraryFileKind, Guid Id)`, a singleton (`Categories`, `Settings`), or a misnamed file (decision 1). `LibraryFileKind`: `Show`, `Service`, `Template`, `ServiceTemplate`, `ServiceState`, `Categories`, `Settings`.
- `Watching/ChangeDebouncer.cs`: `Add(string path, DateTimeOffset at)`, `TakeDue(DateTimeOffset now)`, `NextDueAt`. Paths compared case-insensitively.
- `Watching/LibraryMonitor.cs`: `Scan()` (full pass: remembers hashes, builds problems, returns `LibraryScan` with the loadable files per kind and the problems), `Apply(IEnumerable<string> paths)` returns `LibraryUpdate(Changes, Problems, ProblemsChanged)`, `Problems`, `RecordWrite(path, FileStamp?)` (internal, decision 6), `MarkUnavailable()`.
- `Watching/LibraryChange.cs`, `LibraryProblem.cs`: `LibraryChange(Kind, Guid? Id, ChangeType, Path, FileStamp? Stamp)`; `LibraryProblem(Path, ProblemKind, Message)` with kinds `ConflictCopy`, `CopiedFile`, `UnexpectedFile`, `Unreadable`.
- `Watching/FolderWatcher.cs`: wraps `FileSystemWatcher` (subfolders on, 64 KB buffer), the debouncer, a timer and `IClock`. Raises `Updated(LibraryUpdate)` and `Unavailable`. Buffer overflow triggers a full rescan. `IDisposable`.
- `LibraryFolder.cs`: `Check(string? path)` (decision 9).

**Storage (changed)**
- `LibraryFileStore`: optional write hook, called after each successful write or delete.
- `FolderLibrary`: creates and exposes the monitor (`Monitor`), wiring the hook.

**Tests (named by requirement ID)**
1. **LIB-007 debounce:** 20 events on one path in 300 ms give one due path 500 ms after the last. Two paths flush separately. Nothing is due early. An event during the quiet period restarts it.
2. **LIB-009 names:** table: `{guid}.json` per folder gives kind and Id; `{guid} (1).json`, `… conflicted copy ….json`, `Amazing Grace.json` give the right problem kind; `.saving`, `.tmp`, `~$x.json.tmp`, `desktop.ini`, `media/…`, a subfolder of `shows/` are ignored; extension case doesn't matter; `categories.json`, `library.json`, `service-state/{guid}.json`.
3. **LIB-009 scan:** a temp Library with good files, a conflict copy, a copied Show (`B.json` holding A's Id) and a damaged file: only the good files are loadable, each problem is listed once with its path. A duplicated Service whose Show Copies share Ids with the original raises no problem.
4. **LIB-007 apply:** another process changes a Show gives `Changed` with the new stamp. Rewriting the same bytes gives nothing. A save or delete through `FolderLibrary` gives nothing (self-write). A new file gives `Added`, a deleted one `Removed`. A conflict copy appearing and disappearing updates `Problems` and never gives `Added`. `.saving` files coming and going give nothing.
5. **LIB-013:** a `service-state/` file changed elsewhere gives a `ServiceState` change for that Service. `categories.json` and `library.json` changes are reported.
6. **AS-08 (storage level):** load a Show, another "machine" writes it, the monitor reports `Changed`, saving with the old stamp gives `Conflict` and leaves the file alone, reloading and saving succeeds.
7. **LIB-010:** `Check` for null, missing, a file, an empty folder, a full Library. The monitor reports `Unavailable` when the root is deleted, and a rescan after it comes back reports the differences.
8. **FolderWatcher (real folder, two tests, up to 5 s each):** a file written by another stream reaches `Updated` once. Deleting the root raises `Unavailable` without throwing.

## C1.4b: Search

**Storage (new files)**
- `Search/SearchText.cs`: `Normalize(string)` (decision 11).
- `Search/ICatalogSearch.cs`: `Search(SearchQuery) : IReadOnlyList<SearchHit>`. `SearchQuery(string Text, ShowKind? Kind, Id<Category>? CategoryId)`. `SearchHit(Id<Show> ShowId, string Title, ShowKind Kind, Id<Category> CategoryId, SearchMatch Match)`, `SearchMatch` = `All` (empty query), `TitleStart`, `Title`, `CcliNumber`, `SlideText`.
- `Search/CatalogSearch.cs`: `ICatalogSearch` plus `Load(IEnumerable<Show>)`, `Upsert(Show)`, `Remove(Id<Show>)`, `Apply(LibraryUpdate, ILibrary)` (reloads changed Shows, removes deleted ones). Immutable snapshot (decision 12).

**Tests**
1. **CAT-003:** `Normalize` table (`Él Shaddai`, `SEÑOR`, `Grâce`, punctuation, double spaces). Typing `a`, `am`, `ama`… narrows each time. Case and accents ignored both ways (`senor` finds `Señor`, `Señor` finds `Senor`). Empty query lists all, sorted.
2. **CAT-004:** ranking table: title start above title middle above CCLI number above lyrics. Words in any order. CCLI number matches exactly, not partially. Tokens and slide labels don't match.
3. **CAT-003 filters:** Kind, Category, and both with a query (the Placeholder case of CAT-006).
4. **CAT-005:** `Upsert` with a new title moves the hit, `Remove` drops it, and `Apply` of a monitor update with a changed and a deleted Show updates the index. A Show that is unreadable or in the problems list is not indexed.
5. **Speed (loose bound):** 2,000 Shows of 8 slides, any one-letter query under 50 ms on the build machine.
