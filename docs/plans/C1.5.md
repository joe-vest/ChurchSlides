## Goal

The operator's mental model, as code: a Service is a list of items, each with its slides. The session knows the selected slide (not presenting) or the current slide (presenting), moves by slide or by item, passes over what can't be shown, never wraps, keeps Black/Clear/Logo through navigation, survives the Service changing underneath it, and announces every move in the fixed ACT-005 order so audio (C4.1) and Actions (C5.2) can hook in later. All tested headless.

## How it behaves (the part to check)

| Situation | Behavior |
|---|---|
| Next / Previous | Nearest displayable slide after / before the current one, crossing item boundaries. At either end of the Service: nothing (no wrap). |
| Not displayable | Skipped slides (the skip list in force, `SkipRules.InForce`, so none for cued Shows), unfilled Placeholders, missing Shows, Scripture Items not yet generated, Shows with no slides. They stay in the sequence and in the state. |
| Click a slide (presenting) | `GoToSlide(item, slide)`. Displays it even if Skipped. Next / Previous from it go to the nearest displayable slide either way. |
| Click an item header (presenting) | `GoToItem(item)`: its first displayable slide. An item with none: nothing. |
| Next item / Previous item | First displayable slide of the nearest item after / before the current item that has one. Previous item from the middle of an item goes to the previous item, not back to the top of this one. At the ends: nothing. |
| Go to the current slide | Nothing: no state change, no events (ACT-013). `GoToItem` of the current item from its third slide goes to its first slide (a slide change, not an item change). |
| Not presenting | Clicking selects (slide or item header). Every other navigation and screen command does nothing. Output black (`IsPresenting` false). |
| Go Live / Rehearse | `StartPresenting(mode)`: `ServiceStarted`, then displays the selected slide, or the first displayable slide if nothing is selected. Screen starts Normal. A Service with nothing displayable starts presenting with no current slide. |
| Stop presenting | Back to not presenting. The last current slide becomes the selection, so Go Live resumes there. No `SlideEnded` / `ShowEnded`. |
| Black / Clear / Logo | `ToggleScreen` (operator): on, or off if it was on; one at a time. `SetScreen(Normal/Black/Clear/Logo)` (Actions): sets, no change if already so. Navigation keeps the screen state. |
| Service changed while presenting | `Refresh(service)` rebuilds the sequence and re-anchors by (item, slide). Current slide still there: stays, new state (so an edited slide re-renders), no `SlideDisplayed` (LIVE-040). Current slide or item gone: state keeps it as current with `CurrentRemoved`; Next goes to the first surviving slide that followed it (or the nearest displayable after that), Previous likewise backwards (LIVE-041). |
| Move order (ACT-005) | `ItemChanged` (only on an item change, carries the `Origin`, audio will stop on Operator) → `SlideEnded` → `ShowEnded` (item change only) → new state shown → `ShowStarted` (item change only) → `SlideDisplayed`. Commands issued by a listener during a move run after the move finishes, in order. |

## Decisions for you to confirm

| # | Decision | Recommendation and reason |
|---|---|---|
| 1 | **One session per open Service.** `new PresentationSession(service, findShow)`, then `StartPresenting(mode)`. ARCH 6.1's `StartPresenting(service, mode)` becomes `StartPresenting(mode)`. Opening another Service means a new session (after Stop presenting). | Selection exists before presenting, so the session needs the Service first. No "which Service" state to get wrong. |
| 2 | **Shows are looked up through a function** `Func<Id<Show>, Show?>` that the App backs with its in-memory Library. Null means a missing Show (SVC-026). | Engine stays free of file I/O and of `ILibrary`'s loading. Tests pass a dictionary. |
| 3 | **`ServiceSequence` is in Domain** (ARCH section 3 lists "Service flattening" there), immutable, rebuilt on every `Refresh`. It keeps items as items: `Items[i].Slides[j]` with `IsSkipped` and `IsDisplayable`, plus an item status (`Show`, `MissingShow`, `UnfilledPlaceholder`, `NotGenerated`). The flat order is internal to its searches. | Two levels everywhere (ARCH 5.2). The operator list (C2.2) and the remote (C8.1) render straight from it. |
| 4 | **While not presenting only `Select` and `StartPresenting` do anything.** Next, Previous, item moves, GoTo and screen commands are ignored. Selecting a Skipped slide is allowed and Go Live displays it. | DEC-021: presenting is deliberate. Hotkeys are "while presenting" (LIVE-020). |
| 5 | **Stop presenting fires no `SlideEnded` / `ShowEnded`**, only a `PresentingStopped` event (C5.2 cancels pending Actions on it, C5.1 resets Timers). The screen state is dropped. | An author's `SlideEnded → GoToItem` must not run while the operator is stopping. FRD doesn't say. Confirmed by the owner. |
| 6 | **Starting presenting fires `ServiceStarted`, shows the slide, then `ShowStarted` and `SlideDisplayed`** for the first item and slide. No `ItemChanged` (nothing is being left). | LIVE-009 plus ACT-011 ("entered from any direction"). |
| 7 | **Events are two plain .NET events, raised synchronously on the caller's thread:** `StateChanged(PresentationState)` for the Output, Preview and lists; `EventRaised(PresentationEvent)` for audio and Actions. `PresentationEvent(Kind, ItemId?, SlideId?, Origin)` with `Kind` one of `ServiceStarted`, `ItemChanged`, `SlideEnded`, `ShowEnded`, `ShowStarted`, `SlideDisplayed`, `PresentingStopped`. Step 4 of ACT-005 is the `StateChanged`. | One record with a kind avoids clashing with the Domain trigger types `ShowStarted` etc. Synchronous means each step's zero-delay Actions finish before the next (ACT-005). |
| 8 | **Re-entrant commands are queued.** A command called from inside a `StateChanged` or `EventRaised` handler is queued and runs after the current command finishes, first in first out. | ARCH 6.3: a move never starts inside another. Endless zero-delay loops are the loop guard's job (C5.2). |
| 9 | **A throwing listener doesn't break the move.** Each handler call is guarded, the exception goes to an `Action<Exception>` given to the constructor (the App logs it), and the remaining steps still run. | SAFE-006: the Output must never get stuck half way. One constructor argument, no logging framework in Engine. |
| 10 | **`ICommandApi` in this chunk has only what exists:** `Next`, `Previous`, `NextItem`, `PreviousItem`, `GoToSlide(SlideTarget)`, `GoToItem`, `ToggleScreen`, `SetScreen`, `Select`, `StartPresenting`, `StopPresenting`, each with a `CommandOrigin` as ARCH 6.1 says. Audio and Timer commands join in C4.1 and C5.1. Mode switching mid-presentation (MODE-002) joins in C6.1. | No empty methods. Adding members later is cheap while there is one implementation. |
| 11 | **The session doesn't save the Mode.** `PresentationState.Mode` reports it. The App (C2.2) writes the Service state file when presenting starts. | Engine does no file I/O (ARCH 3). |
| 12 | **Position info counts what the operator sees in the list.** "Item 4 of 9" counts all items. "Slide 2 of 6" counts all slides of the item, skipped ones too. Null while the current slide is removed. | Matches the two-level list, where skipped slides are visible and greyed (LIVE-017). |
| 13 | **`GoToSlide` with no item** looks in the current item (ACT-022). Unknown targets do nothing (ACT-041). A removed selection is simply cleared on `Refresh`. | Simplest rules that meet the FRD. |

## C1.5a: Sequence (Domain)

- `Navigation/ServiceSequence.cs`: `static ServiceSequence Build(Service, Func<Id<Show>, Show?> findShow)`. `Items: ImmutableArray<SequenceItem>`. `SequenceItem(Id<ServiceItem> ItemId, SequenceItemStatus Status, Show? Show, ImmutableArray<SequenceSlide> Slides)`, `HasDisplayable`. `SequenceSlide(Id<Slide> SlideId, bool IsSkipped, bool IsDisplayable)`. `SlideRef(Id<ServiceItem> ItemId, Id<Slide> SlideId)`.
- Searches: `Find(SlideRef)`, `NextDisplayable(SlideRef)`, `PreviousDisplayable(SlideRef)`, `FirstDisplayable()`, `FirstDisplayableOf(itemId)`, `NextItemWithDisplayable(itemId)`, `PreviousItemWithDisplayable(itemId)`, `Contains(SlideRef)`, `All` (flat order, used for LIVE-041).
- Skip list from `SkipRules.InForce` for both item kinds (STATUS follow-ups). Scripture Items: the generated Show, never skipped.

**Tests (`ServiceSequenceTests`)**
1. **LIVE-006 / SVC-034 / SVC-026:** a Service with a song (two skipped slides), an unfilled Placeholder, a missing Show, an ungenerated Scripture Item, a Show with every slide skipped and an empty Show: every item and slide listed, only the right ones displayable.
2. **SVC-025:** a cued Show with a stale skip list: all slides displayable, `IsSkipped` false.
3. **SVC-021 copies:** a Show Copy's skip list is honored.
4. **LIVE-005 / LIVE-007:** next/previous across boundaries, past non-displayable items, null at both ends.
5. **LIVE-017:** next/previous from a skipped slide.
6. **LIVE-016:** next/previous item past items with nothing displayable; null at the ends.

## C1.5b: Session (Engine)

- `CommandOrigin { Operator, Automation }`. `ScreenState { Normal, Black, Clear, Logo }`.
- `ICommandApi` (decision 10).
- `PresentationState`: `Service`, `Sequence`, `IsPresenting`, `Mode?`, `Selected: SlideRef?`, `Current: SlideRef?`, `CurrentRemoved`, `ItemNumber`, `ItemCount`, `SlideNumber`, `SlideCount` (decision 12), `NextSlide: SlideRef?` (LIVE-008, no Action prediction), `NextItemId?`, `Screen`.
- `PresentationEvent`, `PresentationEventKind` (decision 7).
- `PresentationSession : ICommandApi`: constructor `(Service, Func<Id<Show>, Show?>, Action<Exception> onListenerError)`, `State`, `StateChanged`, `EventRaised`, `Refresh(Service)`. Keeps the old flat order while the current slide is removed (LIVE-041).

**Tests (`PresentationSessionTests`, recording one merged log of states and events)**
1. **AS-02:** Go Live, Next until nothing changes: visits exactly the displayable slides in order, crossing every item, then Next does nothing.
2. **LIVE-005:** Previous from an item's first slide lands on the previous item's last displayable slide.
3. **LIVE-016:** Next item / Previous item / item header, including from mid-item, from a skipped slide, and an item with nothing displayable (does nothing).
4. **LIVE-017:** clicking a skipped slide displays it; Next and Previous from it.
5. **ACT-013:** going to the current slide: no state, no events.
6. **ACT-005:** event order for a slide change within an item, an item change by the operator and by automation (`ItemChanged` carries the origin), and Go Live (decision 6).
7. **ACT-005 queueing:** a listener calling `Next` inside `SlideDisplayed` runs after the move, with its own complete event sequence.
8. **SAFE-006:** a throwing listener reaches `onListenerError` and the move still completes.
9. **DEC-021 / LIVE-009 / LIVE-018 / MODE-005:** not presenting, click selects only and fires nothing else; Next ignored; Go Live starts at the selection, or the first displayable slide; Mode in the state; Stop returns to not presenting with the last slide selected and fires only `PresentingStopped`.
10. **LIVE-013 / LIVE-014 / ACT-026..028 / ACT-033:** toggles exclusive and off on second press; `SetScreen` sets without toggling and `Normal` clears; navigating keeps the screen state.
11. **LIVE-008:** `NextSlide` in the state follows skips and items, null at the end.
12. **LIVE-040:** `Refresh` with an edited current slide gives a new state, no events; position re-anchored after items are inserted above.
13. **LIVE-041:** current slide removed, then current item removed: state keeps it, Next and Previous go to the old neighbours; everything after it removed: Next does nothing.
14. **ACT-022 / ACT-041:** `GoToSlide` without an item uses the current item; unknown item or slide does nothing.
