# C1.3: Storage foundation

Size M. Project: `ChurchSlides.Storage` (BCL only, no packages, no WPF) plus `ChurchSlides.Storage.Tests` (temp folders only).
FRD: LIB-001, LIB-002, LIB-003 (path rule only), LIB-004 (migration and read-only), LIB-005, LIB-006 (save-time check only), LIB-008, SAFE-001/002 (the draft store, not the editing UI).
ARCH: section 8.1, 8.3, 9.1.

**Status: agreed by the owner 2026-11-23 (all ten decisions). Ready to execute.**

## Goal

Read and write every Library object as a plain JSON file, safely. A save is atomic, never overwrites a file that changed on disk since it was loaded, and never touches a file from a newer schema. Machine-local data has its own home outside the Library. Everything is tested against a temp folder with `dotnet test`.

## Split into two commits

| Sub-chunk | Scope |
|---|---|
| **C1.3a: Library files** | Layout, atomic writer, stamps, repositories, save validation, migration chain, `ILibrary` |
| **C1.3b: Local data and drafts** | `LocalDataPaths`, `LocalSettings`, `IDraftStore` and its file implementation |

## Decisions for you to confirm

| # | Decision | Recommendation and reason |
|---|---|---|
| 1 | **`ILibrary` lives in `Storage`, not `Engine`.** | ARCH section 3 says Engine "owns" it, but the dependency rule has Engine reference Storage, so an interface in Storage is the only layering that works. Engine tests can still fake it. |
| 2 | **The API is synchronous.** Callers (view-models, the watcher) put it on a background thread when they need to. | Files are a few KB. No `async` means fewer modes and simpler tests. Retry waits happen inside the writer. |
| 3 | **A conflict means the file's content hash differs from the one recorded at load.** The last-write time is recorded too (LIB-006) but only as a cheap hint for the watcher (C1.4). A file that Drive merely "touched" without changing content is not a conflict. | Hash is the truth. Timestamps lie on synced folders. |
| 4 | **Saving content identical to what is on disk writes nothing.** | Fewer sync events, no pointless Drive churn. |
| 5 | **The repository refuses to save over a file whose schema is newer than the app.** Result `ReadOnlyNewer`, whatever the caller passes. | LIB-004. Enforced in one place rather than trusted to each editor. |
| 6 | **Save refuses invalid objects:** empty `Id` anywhere (Show, Slide, Text Box, Service, Service Item, Template, Template Box, Category and so on) or an empty required name (Show title, Service, Template, Service Template and Category names). Result `Invalid` with a list of problems. | Follow-up from C1.1: the model dropped `required`, so this is the safety net. |
| 7 | **Migrations rewrite the JSON before deserializing.** They are in memory only. The file on disk is not rewritten until the user next saves, and the stamp is of the original bytes. | LIB-004 "migrates in memory". Opening a Library never churns files, and the conflict check stays correct. There are no real migration steps yet (every kind is version 1), so the chain is tested with fake steps. End to end tests come with the first real schema bump (Follow-up). |
| 8 | **Delete also takes the expected stamp** and refuses if the file changed. | Deleting something edited on the other machine is the same data loss as overwriting it. |
| 9 | **`LocalSettings` in this chunk holds only `LibraryPath`.** Other machine-local settings (output display, remote token, window positions) are added by the chunk that needs them. | Simplicity. Rule 9: don't widen the diff. |
| 10 | **Draft files carry the stamp of the Library file they were based on.** On restore, the caller can tell the draft is stale. The draft's age is the file's last-write time (no clock needed). | SAFE-004 (C9.x) needs this to avoid restoring over a newer synced version. The 30 s autosave timer itself belongs to the editor (C2.3). |

## C1.3a: Library files

New code in `ChurchSlides.Storage/`.

**Types**
- `LibraryLayout(root)`: paths for `library.json`, `categories.json`, `shows/`, `services/`, `templates/`, `service-templates/`, `media/`. File name of an object is `{id}.json`. Contents win over the name (ARCH 9.1), so loading by ID reads that name and reports a mismatch for C1.4 to handle (`LoadedFile.NameMatchesId`).
- `FileStamp(DateTime LastWriteUtc, string Sha256)`: computed from the file's bytes.
- `LoadedFile<T>(LoadResult<T> Result, FileStamp Stamp, string Path, bool NameMatchesId)`: the value, how it loaded (`Ok`, `ReadOnlyNewer`, `Unreadable`), and the stamp to hand back on save. `NeedsMigration` never escapes: the loader migrates first.
- `SaveResult(SaveOutcome Outcome, FileStamp? Stamp, FileStamp? DiskStamp, IReadOnlyList<string> Problems, string? Error)`. Outcomes: `Saved`, `Unchanged`, `Conflict`, `ReadOnlyNewer`, `Invalid`, `IoFailed`.
- `AtomicFileWriter`: writes `{name}.saving` (UTF-8, no BOM, the `VersionedFile.Serialize` text as-is), flushes to disk, then `File.Replace` over the target, or `File.Move` when the target is new. Retries on `IOException` and `UnauthorizedAccessException` (default 5 tries, 100 ms apart, both settable so tests pass 0). Deletes its own `.saving` on failure. Never deletes a `.saving` it didn't write.
- `IObjectRepository<T>` for Shows, Services, Templates, Service Templates: `Load(id)`, `LoadAll()` (includes unreadable files with their error, skips `.saving` and non-`.json`, tolerates a missing folder), `Save(value, expected)` (`expected` null means "must not exist yet"), `Delete(id, expected)`.
- `ISingletonRepository<T>` for `categories.json` and `library.json`: `Load()` (a missing file gives defaults and a null stamp), `Save(value, expected)`.
- `ILibrary`: `Shows`, `Services`, `Templates`, `ServiceTemplates`, `Categories`, `Settings`, `Layout`. `FolderLibrary` is the implementation. It creates folders on first save, not on open.
- `SaveValidation`: walks the object and returns problems (decision 6).
- `MigrationChain` and `IMigrationStep` (kind, from version, `JsonNode` in and out). A gap in the chain makes the file `Unreadable` with a message naming the missing step.

**Tests (named by requirement ID)**
1. **LIB-002:** each kind round trips through a real file in the right folder with the right name. `LoadAll` returns every file. A missing folder gives an empty list.
2. **LIB-005:** a `.saving` file beside a good file is ignored by `LoadAll` and doesn't change the loaded value. A failure injected between write and replace leaves the original file byte-identical and removes its own `.saving`. A stale `.saving` from a "crash" doesn't block the next save. Output has no BOM.
3. **LIB-005 retry:** a locked target succeeds once released within the retries and gives `IoFailed` (not an exception) when it never is.
4. **LIB-006:** load, change the file on disk, save gives `Conflict` with the disk stamp and the file is untouched. Touching the file without changing it (new write time, same bytes) is not a conflict. Save with a stale stamp after our own earlier save gives `Conflict`. A new object saved over an existing file gives `Conflict`. Delete follows the same rule (decision 8).
5. **Decision 4:** unchanged content gives `Unchanged` and the write time doesn't move.
6. **LIB-004:** a file with a newer version loads `ReadOnlyNewer` and `Save` returns `ReadOnlyNewer` without touching it. A damaged file is `Unreadable` with the file name in the error and doesn't stop `LoadAll`. Migration chain on JSON: single step, multi step, gap, newly required field added to an old file (decision 7).
7. **Decision 6, validation:** table of invalid objects (empty Show ID, empty Slide ID deep inside, blank title, empty Service Item ID) gives `Invalid` with each problem listed and nothing written.
8. **LIB-001/003:** files written contain no drive letter or rooted path. A `LibraryLayout` rooted at a path with spaces and accents works.
9. **LIB-008:** the Library folder contains nothing but the layout above after a full session of saves (no caches, drafts, or settings land in it).

## C1.3b: Local data and drafts

- `LocalDataPaths(root)`: `settings.json`, `cache\images`, `cache\bibles`, `cache\search.idx`, `drafts\`, `logs\app.log`, `last-session.json` (ARCH 9.1). `LocalDataPaths.Default()` resolves `%LOCALAPPDATA%\ChurchSlides`. Only `settings.json` and `drafts\` are used in this chunk. Paths are given out, directories are created when something writes.
- `LocalSettings { LibraryPath }` with its own small versioned file and `ILocalSettingsStore` (`Load`, `Save`, atomic, same writer). Missing or damaged file gives defaults and never throws. Absolute path is allowed here and only here (LIB-001).
- `IDraftStore` and `FileDraftStore`: `Save(kind, id, text, baseStamp)`, `Load(kind, id)`, `List()`, `Discard(kind, id)`. One file per draft under `drafts\{kind}\{id}.json`. A draft is a small wrapper holding the base stamp and the exact `VersionedFile` text of the object. Atomic writes.

**Tests**
1. **LIB-008:** `LocalDataPaths` is outside the Library root and well formed. Settings round trip, missing file gives defaults, damaged file gives defaults.
2. **SAFE-001/002:** a draft saved leaves the Library folder byte-identical (hash of every file before and after). Draft round trips, lists, discards. A second save of the same draft replaces the first. A damaged draft file is skipped by `List` and reported, not thrown.
3. **Decision 10:** a draft remembers its base stamp, and a test shows the stamp differs from the Library file's current stamp after that file changes, so a caller can tell it's stale.

## Deviations found while executing

| Plan said | What was built |
|---|---|
| `SaveOutcome`: Saved, Unchanged, Conflict, ReadOnlyNewer, Invalid, IoFailed | Also `Deleted`, so `Delete` can share `SaveResult`. Deleting a file that is already gone gives `Unchanged`. Deleting a newer-schema file gives `ReadOnlyNewer`. |
| Conflict rules (decision 3) | Saving with a stamp when the file was deleted elsewhere is also a `Conflict` (`DiskStamp` null). Saving a new object (null stamp) when the file exists is a `Conflict` even if the content is identical. |
| `LoadedFile<T>.Stamp` | Nullable: null only for a singleton that doesn't exist yet. |
| `LocalSettings` "own small versioned file" | A flat `{ "schemaVersion": 1, "libraryPath": ... }`. Machine-local, so no newer-schema read-only rule. |
| Draft restore "reports" damaged drafts | `DraftListing(Drafts, Problems)`. |
| Test count | 61 storage tests (263 domain and 14 architecture tests unchanged). |
